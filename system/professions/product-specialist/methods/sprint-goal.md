# Meta da Sprint — outcome, não output

Base: Guia do Scrum 2020 — a meta é o único objetivo da sprint; cria coerência e foco, e dá
flexibilidade sobre o trabalho exato para atingi-la.

## Quando usar

Ao planejar/documentar uma sprint. Entrada: os itens do backlog da sprint (ou o contexto
que os descreve).

## O princípio

**Output** = o que o time entrega (funcionalidade, tela, código).
**Outcome** = a mudança de comportamento ou ganho que o usuário/negócio experimenta.
A meta é o outcome. "Implementar tela de login com OAuth" ❌ → "Usuários acessam o sistema
de forma segura e sem fricção" ✅.

## Barra de qualidade

- **Uma única frase** — sem "e"/"ou"/bullets. Meta composta = escolha o item de maior
  valor e foque nele.
- **Verificável** — dá para saber se foi atingida ("como saberemos?").
- **Fio condutor real**: a meta nasce do tema de valor que une os itens. Itens
  heterogêneos demais → avise (anti-padrão), construa em torno do de maior impacto.
- **Co-criada**, não imposta — a proposta é insumo para o time, alerte se vier top-down.
- Anti-padrões a alertar: lista de tasks, meta vaga ("melhorar o sistema"), meta de
  output, "e/ou".

## Contrato de output

2-3 opções de meta (perspectiva do usuário / do negócio / técnica quando couber), cada uma
com: a frase, por que é outcome, como verificar. Fechar com recomendação justificada e
alertas de anti-padrão detectados no backlog.
