# Comunicação de incidente (visão de produto)

## Quando usar / quando não

- Use quando usuários são afetados: indisponibilidade, dado errado, comportamento que quebra
  a operação de alguém.
- Não use para incidente interno sem efeito externo — aí é conversa técnica.

## Barra de qualidade

- Avisa **antes** de o cliente descobrir sozinho, mesmo sem ter a causa: o que está
  acontecendo, quem é afetado, o que fazer enquanto isso.
- Sem promessa de prazo que não se sustenta; próxima atualização com horário marcado vale
  mais que estimativa otimista.
- Linguagem de impacto ("não é possível enviar vistoria"), não de causa técnica.
- Uma fonte de verdade e um porta-voz; várias versões circulando pioram o incidente.
- Fechamento com o que aconteceu, o que foi corrigido e o que muda para não repetir — sem
  culpar pessoa.
- Efeito colateral no dado (registro perdido, duplicado) é dito, mesmo quando é constrangedor.

## Contrato de output

Aviso inicial (impacto, afetados, contorno, próxima atualização) · atualizações no horário
prometido · fechamento com correção e prevenção · pendências de dado.
