# Roadmap

## Quando usar / quando não

- Use para comunicar direção a quem está fora do time e alinhar sequência entre times.
- Não use para prometer data item a item — isso é plano de release, e roadmap com data
  falsa queima confiança.

## Barra de qualidade

- Organizado por **outcome ou problema**, não por lista de features.
- Horizonte com confiança decrescente (agora / próximo / depois). Precisão no "depois" é
  ficção; o item distante é tema, não escopo.
- Cada item ligado a evidência, ou marcado como aposta.
- O que foi deliberadamente deixado fora aparece — roadmap sem exclusão não é escolha.
- Condição de replanejamento declarada: o que precisa acontecer para a ordem mudar.

## Contrato de output

Agora / próximo / depois, com outcome, evidência ou aposta e nível de confiança · fora de
escopo declarado · gatilhos de replanejamento.
