# Dívida técnica (visão de produto)

## Quando usar / quando não

- Use quando o time pede espaço para dívida, quando incidentes se repetem, ou quando a
  velocidade cai sem explicação de escopo.
- Não use para arbitrar preferência de estilo de código.

## Barra de qualidade

- Dívida traduzida em **consequência de negócio**: tempo de entrega, risco de incidente,
  custo operacional, bloqueio de roadmap. "Código feio" não prioriza nada.
- Custo de conviver estimado junto com o custo de pagar — a comparação é a decisão.
- Escolha explícita: pagar agora, pagar depois (com data de revisão) ou conviver
  conscientemente.
- Percentual fixo de capacidade é um acordo possível, não uma regra universal; sem
  consequência declarada, vira orçamento sem prestação de contas.

## Contrato de output

Itens com sintoma, consequência mensurável, custo de pagar, custo de conviver ·
recomendação e data de revisão.
