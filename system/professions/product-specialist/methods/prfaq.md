# PR/FAQ — trabalhar de trás para frente

## Quando usar / quando não

- Use antes de construir, para decidir se a coisa merece existir e alinhar visão entre
  áreas.
- Não use para documentar requisito de algo já aprovado (isso é `user-story.md` e o
  documento consolidado).

## Barra de qualidade

- Escrito como se já tivesse lançado, em linguagem de cliente — sem jargão interno, sem
  nome de módulo.
- Benefício concreto e verificável; superlativo sem número é sinal de ideia fraca.
- FAQ enfrenta a pergunta difícil (custo, risco, canibalização, o que deixamos de fazer),
  não a fácil.
- Citação de cliente hipotética é marcada como hipotética.
- Se o texto não convence sem adjetivo, o problema é a ideia — isso é diagnóstico, não
  questão de escrita.

## Contrato de output

Manchete e subtítulo · problema · solução · citação (real ou marcada como hipotética) ·
FAQ com as perguntas difíceis · o que precisa ser verdade para dar certo.
